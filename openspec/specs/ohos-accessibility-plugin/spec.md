## Requirements
### Requirement: tauri-plugin-accessibility SHALL 在 OHOS 暴露最小无障碍查询 API
plugins-workspace SHALL 新建 `tauri-plugin-accessibility`(OHOS 专属,huawei-account 形态),经 `openharmony-ability-plugin-accessibility` facade 提供命令 `get_font_scale` / `is_screen_reader_enabled` / `is_touch_explore_enabled`,在插件 setup 中注册 `AccessibilityBridgePlugin`(失败仅记日志,不阻断启动)。

#### Scenario: fontScale 查询
- **WHEN** JS 调用 `getFontScale()`
- **THEN** SHALL 返回系统字号缩放(number,默认 1.0),无需任何权限

#### Scenario: 屏幕阅读器状态查询(权限被拒)
- **WHEN** 系统拒绝 `ohos.permission.ACCESSIBILITY`(三方应用)
- **THEN** `isScreenReaderEnabled()` SHALL reject 并携带结构化错误信息,SHALL NOT 静默返回 false 或 panic

#### Scenario: 非 OHOS 平台
- **WHEN** 在 Windows/macOS/Linux 编译该插件
- **THEN** crate SHALL 编译为 stub,命令返回 `Unsupported` 错误,SHALL NOT 引入 openharmony-ability 依赖

### Requirement: 状态变化事件 SHALL 经 Tauri 事件通道暴露
插件 setup SHALL 自动订阅 facade 的 state-change handler(spawn 线程完成订阅,禁止主线程阻塞),handler 内仅 `app_handle.emit("accessibility-state-changed", enabled)`;JS API `onAccessibilityStateChange(handler)` SHALL 封装 `listen`,返回 UnlistenFn。SHALL NOT 暴露 subscribe/unsubscribe 命令。

#### Scenario: 开关屏幕阅读器触发事件
- **WHEN** 用户在系统设置开/关屏幕阅读器且 JS 已注册 handler
- **THEN** handler SHALL 收到 boolean payload(新状态)

#### Scenario: 多 JS listener
- **WHEN** JS 注册多个 `onAccessibilityStateChange` handler
- **THEN** 每个 handler SHALL 各收到一次事件(Tauri 事件扇出),原生订阅保持单份

### Requirement: permissions 与 capabilities SHALL 按插件规范声明
`permissions/default.toml` SHALL allow 三个查询命令;`build.rs` SHALL 声明 COMMANDS 生成 autogenerated 权限;examples/api `capabilities/ohos-plugins.json`(platforms=["openHarmony"])SHALL 加 `accessibility:default`。

#### Scenario: 未授权调用
- **WHEN** capability 未包含 accessibility 权限的窗口调用命令
- **THEN** 命令 SHALL 被 ACL 拒绝(标准插件权限行为)

### Requirement: examples/api SHALL 含真机验证用例
plugins.ts SHALL 含 auto 类用例(fontScale 返回值为正 number;touch-explore/screen-reader 查询不 panic)与 manual 类用例(开关屏幕阅读器触发事件回调,console 指引模式)。

#### Scenario: auto 用例
- **WHEN** 测试套件运行 `@tauri-apps/plugin-accessibility.getFontScale`
- **THEN** SHALL 断言返回值为正 number

### Requirement: R230 spec SHALL 修订为最小 API 边界声明
`ohos-platform-limitations` 的 R230 SHALL 从"SHALL NOT 提供无障碍 API"修订为:最小查询/事件 API 由 `tauri-plugin-accessibility` 提供(指向 ohos-accessibility-plugin spec),Web 内容无障碍仍由 ArkWeb ARIA 处理,`AccessibilityExtensionAbility` 仍不可用(三方不可注册)。

#### Scenario: 边界查询
- **WHEN** 开发者查询 OHOS 无障碍能力边界
- **THEN** spec SHALL 指明可用的最小 API 与不可用项(服务提供方/ARIA 归属)
