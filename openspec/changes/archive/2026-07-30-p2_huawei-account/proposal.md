## Why

Phase 1 已在 `openharmony-ability` 仓内完成华为账号一键登录的底层桥接(`HuaweiAccount::{login,silent_login,logout}` 异步公共 API,返回 `AccountInfo`),并重建 `ability.har`。但该能力尚未对前端可用——Tauri 应用无法经 `invoke` 调用账号登录。本 Phase 新建 `tauri-plugin-huawei-account` 纯 Rust+JS 薄插件,把 Phase 1 的底层 API 暴露为 Tauri 命令,供前端 `@tauri-apps/plugin-huawei-account` 调用,并在非 OHOS 平台返回 `unsupported` stub。插件**无业务 ArkTS**(铁律 1:Account Kit 调用已收口在 openharmony-ability)。

## What Changes

- 新建 `plugins-workspace/plugins/huawei-account/` 插件 crate:
  - Rust 侧:`lib.rs`(Builder + `init()` + 双 `build()` cfg)、`ohos.rs`(`cfg(target_env="ohos")` 真实命令,经 `openharmony_ability::HuaweiAccount::new()` 直接 await,绕开 `run_mobile_plugin`/`dispatch_run_command`/`PENDING_PLUGIN_CALLS` 管道,仿 updater/autostart)、`commands.rs`(`cfg(not(target_env="ohos"))` desktop stub 返回 `Unsupported`)、`error.rs`(`Error` 枚举:Unsupported/Cancelled/NotLoggedIn/Other,从 napi reason `"rejected: <code>:<msg>"` 解析 code 分类 + `Serialize`)、`models.rs`(插件本地 `AccountInfo`,驼峰 serde,ohos 侧从 `openharmony_ability::AccountInfo` 转换)、`build.rs`(tauri-plugin ACL 自动生成)。
  - JS 侧:`guest-js/index.ts`(`login`/`silentLogin`/`logout` 调 invoke)、`package.json`/`rollup.config.js`/`tsconfig.json`。
  - 权限:`permissions/{default.toml,allow-login.toml,allow-silent-login.toml,allow-logout.toml}` + `autogenerated/`。
  - `Cargo.toml`:`cfg(target_env="ohos")` 下 `openharmony-ability = { path = "../../../openharmony-ability/crates/ability", features = ["account"] }`(account 不在 default,需显式启用;Cargo feature 统一使 account 在整个构建生效,不碰 tauri 核心 crate)。
- `examples/api/src-tauri/Cargo.toml` 加 `tauri-plugin-huawei-account = { path = "../../../../plugins-workspace/plugins/huawei-account" }`;`src/lib.rs` 加 `.plugin(tauri_plugin_huawei_account::init())`。
- 本 Phase 仅做插件骨架 + 编译打通 + 命令可 invoke;**不含**设备端真实登录(Phase 3)、前端测试用例(Phase 4)。

## Capabilities

### New Capabilities
- `huawei-account`: Tauri 插件层华为账号一键登录能力——暴露 `login`/`silent_login`/`logout` 三个 invoke 命令,OHOS 上路由到 `openharmony_ability::HuaweiAccount` 并返回 `AccountInfo`(登录流仅 `openId`/`unionId`/`authorizationCode` 非空,资料字段空,见 p1 design D9 选项 A),非 OHOS 平台返回 `unsupported`;错误按 code 分类(不支持/取消/未登录/其他)透传给前端。

## Impact

- **代码**:`plugins-workspace/plugins/huawei-account/` 新建 ~14 文件;`examples/api/src-tauri/{Cargo.toml,src/lib.rs}` 改 2 文件。
- **API**:新增 `tauri-plugin-huawei-account` crate + 3 个 invoke 命令 + JS API;不改变 openharmony-ability 既有 API(仅消费 `account` feature)。
- **依赖**:插件 OHOS 侧新增对 `openharmony-ability`(本地 path,`account` feature)的依赖;无新外部 crate(复用 tauri/serde/serde_json/thiserror)。
- **平台隔离**:OHOS 真实实现经 `cfg(target_env="ohos")` 隔离;desktop/mobile stub 经 `cfg(not(target_env="ohos"))` 返回 `Unsupported`,不影响 Windows/macOS/Linux 既有构建。openharmony-ability 依赖仅 OHOS target 引入。
- **ACL**:新增 `huawei-account` 权限集(default + 3 allow),需在 examples/api capabilities 授权(Phase 3 处理 capabilities,本 Phase 仅出权限定义文件)。
- **关联**:依赖 p1(`openharmony-ability/account`)已完成;本 Phase 的 examples/api hvigor 构建将是 p1 ArkTS `account.ets` 的首次真实编译(p1 已通过 demo 工程单独验证)。
