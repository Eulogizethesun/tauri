# Design: p2-ohos-accessibility

## Context

Phase 1a(p1-ohos-accessibility,已实现)交付了 bridge 层:
- ArkTS `AccessibilityPlugin`(id=`ohos.accessibility`,requires=["ability"],EntryAbility 模板/gen 已注册,pack-plugins 计 16)
- Rust facade `openharmony-ability-plugin-accessibility`:`AccessibilityBridgePlugin`、`AccessibilityClient`(`AccessibilityExt::accessibility(&OpenHarmonyApp)` 构造)、`AccessibilityError`

plugins-workspace 已有两个可仿写的先例:**huawei-account**(OHOS 专属纯命令插件,其他平台 stub)与 **clipboard-manager**(setup 里 `register_plugin` + 经 facade client 调 bridge action)。

## Goals / Non-Goals

**Goals**
- plugins-workspace 新建 `tauri-plugin-accessibility`,JS API:`getFontScale` / `isScreenReaderEnabled` / `isTouchExploreEnabled` / `onAccessibilityStateChange`
- examples/api 接入 + 真机验证(fontScale 返回值、screen-reader 查询权限实测、状态事件触发)
- R230 spec 修订

**Non-Goals**
- `AccessibilityExtensionAbility`(无障碍服务提供方,三方不可注册)
- Web 内容无障碍(ArkWeb 内置 ARIA)
- 其他平台的真实实现(非 OHOS 平台返回 Unsupported stub)

## Decisions

### D1: 插件形态 — huawei-account 骨架 + clipboard-manager 的 register_plugin

crate 结构仿 huawei-account(OHOS 专属、其他平台 stub、无 setup state):

```
plugins-workspace/plugins/accessibility/
├── Cargo.toml        # [target.'cfg(target_env = "ohos")'.dependencies] 指向 facade path
├── build.rs          # tauri_plugin::Builder::new(COMMANDS)
├── src/lib.rs        # Builder/init,OHOS 与非 OHOS 双分支 invoke_handler
├── src/ohos.rs       # OHOS 命令实现(经 AccessibilityClient)
├── src/commands.rs   # 非 OHOS stub(Error::Unsupported)
├── src/error.rs      # thiserror Error
├── permissions/default.toml + autogenerated(build.rs 产)
├── guest-js/index.ts + package.json + rollup.config.js + tsconfig.json
```

区别于 huawei-account 的一点:accessibility 需要 Rust 侧 `register_plugin(AccessibilityBridgePlugin)`(否则 ArkTS lookup 报 "not installed"),采用 clipboard-manager desktop.rs 先例——在插件 Builder 的 OHOS `setup` 里注册,失败仅 log::error 不阻断启动。

### D2: 命令 — 3 个查询命令,async + 直接 await(huawei-account 模式)

| 命令 | facade 调用 | 说明 |
|---|---|---|
| `get_font_scale` | `client.get_font_scale()` | 零权限,返回 f64 |
| `is_screen_reader_enabled` | `client.is_open_accessibility()` | 权限 `ohos.permission.ACCESSIBILITY`(系统级),三方被拒时返回明确错误(不静默 false) |
| `is_touch_explore_enabled` | `client.is_touch_explore_enabled()` | 同上权限边界 |

命令为 `async fn`,`tauri::ohos::APP` 的 MutexGuard 用块作用域在 `.await` 前 drop(huawei-account ohos.rs 先例:`!Send` guard 不得跨 await)。不用 futures_executor::block_on(命令本就跑在 worker 线程,直接 await 即可,无主线程死锁风险)。

错误面:`Error::Unsupported`(非 OHOS)、`Error::Accessibility { message }`(bridge 错误透传,含 facade 映射后的权限拒绝信息)。

### D3: 事件 — setup 自动订阅 + app.emit,JS 用 listen(不加订阅命令)

事件链路:

```
ArkTS accessibility.on("screenReaderStateChange")
  → invokeNativeSync("accessibility-state-changed")
  → Rust on_main_thread_event → dispatch_state_change → STATE_CHANGE_HANDLER
  → 插件 setup 注册的 handler:NAPI 主线程,仅 app_handle.emit(...) (非阻塞)
  → JS listen("accessibility-state-changed", e => e.payload /* boolean */)
```

关键决策:**在插件 setup 里自动订阅**(而非暴露 subscribe/unsubscribe 命令):
- JS API 因此是纯 `listen` 形态(`onAccessibilityStateChange` 返回 UnlistenFn),与 notification 等插件的事件消费习惯一致,免去 JS 侧 invoke+listen 配对
- setup 跑在主线程,**不能 block_on/await** bridge 调用(死锁铁律)→ setup 内 `std::thread::spawn` + `futures_executor::block_on(client.subscribe_state_change(...))` 完成订阅,失败仅 log
- handler 槽是 facade 全局单槽(STATE_CHANGE_HANDLER),自动订阅恰好一一对应;ArkTS 侧订阅幂等,插件重复 init 也安全
- handler 在 NAPI 主线程执行,只做 `app_handle.emit`(thread-safe、非阻塞),满足"keep it cheap"约束

事件名:`accessibility-state-changed`,payload 为 boolean(屏幕阅读器新状态)。

### D4: JS API 形态(guest-js)

```ts
import { invoke } from '@tauri-apps/api/core'
import { listen, type UnlistenFn } from '@tauri-apps/api/event'

export async function getFontScale(): Promise<number>
export async function isScreenReaderEnabled(): Promise<boolean>
export async function isTouchExploreEnabled(): Promise<boolean>
export async function onAccessibilityStateChange(handler: (enabled: boolean) => void): Promise<UnlistenFn>
```

`onAccessibilityStateChange` = `listen('accessibility-state-changed', ...)` 的薄封装(原生订阅由插件 setup 常驻,JS 层多 listener 由 Tauri 事件扇出天然支持)。

### D5: permissions / capabilities

- `permissions/default.toml`:`allow-get-font-scale` / `allow-is-screen-reader-enabled` / `allow-is-touch-explore-enabled` 三条(事件无命令,不需要权限条目)
- `build.rs`:`tauri_plugin::Builder::new(&["get_font_scale", "is_screen_reader_enabled", "is_touch_explore_enabled"])`,autogenerated 由构建产出
- examples/api `capabilities/ohos-plugins.json`(`platforms: ["openHarmony"]`)加 `"accessibility:default"`
- 权限申明:不需要在 module.json5 加 `ohos.permission.ACCESSIBILITY`(系统级权限,三方声明了也批不下来;查询被拒时 API 返回错误即可,p2 真机实测确认行为)

### D6: examples/api 集成

- `src-tauri/Cargo.toml` → `[target.'cfg(target_env = "ohos")'.dependencies]` 加 `tauri-plugin-accessibility = { path = "../../../../plugins-workspace/plugins/accessibility" }`
- `src/lib.rs` OHOS 块加 `.plugin(tauri_plugin_accessibility::init())`
- 前端测试用例(plugins.ts):
  - auto 类:`plugin:accessibility|getFontScale`(断言 number 且 >0)、`isTouchExploreEnabled` 的**错误路径**(被拒时返回错误而非崩溃——真机实测前无法预断成功,用例按"返回 boolean 或结构化错误皆可接受、不 panic"断言)…… 实测通过后收紧为断言 boolean
  - manual 类:开/关系统屏幕阅读器触发 `onAccessibilityStateChange` 回调(console 指引,同 global-shortcut.triggerCallback 模式)

### D7: dist-js 构建

`npm run build`(rollup `createConfig()`)产 `dist-js/{index.js,index.cjs,index.d.ts}`,构建后校验非 0 字节(sql 陷阱);examples/api 经 Vite 按包名 `@tauri-apps/plugin-accessibility` 解析。

## Risks / Trade-offs

- [`isScreenReaderEnabled` 权限被系统拒绝(201)] → API 返回携带 facade 错误信息的 `Error`,manual 测试用例记录实测结果;若确拒,在 README/spec 标注"查询需系统权限,三方应用大概率被拒"
- [setup 自动订阅的 spawn 线程与 APP 初始化时序] → clipboard-manager 先例证明插件 setup 时 `tauri::ohos::APP` 已可用;订阅失败仅 log,查询命令不受影响
- [状态事件在无障碍服务未安装的设备上永不触发] → 可接受,manual 用例注明前置条件

## Migration Plan

纯新增。回滚 = 删插件目录 + examples/api 三处接入点 + capabilities 一行。R230 spec 修订独立可回滚。

## Resolved Questions

- ✅ **三方应用调用 `isOpenAccessibility` 是否真被 201 拒绝** — **未被拒绝**。真机（HUAWEI MateBook Pro 2in1）hilog 显示 `is-open-accessibility` / `is-touch-explore-enabled` 两个 bridge action 均完整走通并返回 Response，无任何权限拒绝/201/BusinessError 记录；文档宣称的 `ohos.permission.ACCESSIBILITY` 系统级权限对三方只读查询实际不设防（与 huawei-account 的 acl 例外不同，此处普通签名即可用）。
- ✅ **screenReaderStateChange 事件订阅** — **订阅注册成功**。插件 setup 的 `subscribe-state-change` bridge call 完整走通，系统日志 `accessibility_asacfwk: SubscribeStateObserver: Observer has subscribed!`（×6，多次注册幂等）确认 observer 已挂上。事件触发的完整端到端（人工开关屏幕阅读器→JS 回调收 payload）留 manual 用例 `onAccessibilityStateChange` 人工验证，订阅链路本身已实锤可用。
- ✅ **fontScale 返回值** — auto 用例 `getFontScale` ✅ 29ms，返回正有限数（`fontSizeScale` 属性名修复后生效）。
